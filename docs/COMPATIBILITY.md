# Forge 1.12.2 兼容性调整依据

本记录只涉及开发工具链，不实现游戏机制，不修改 Minecraft、Forge、Thaumcraft 或 Baubles 的下载原件。ForgeGradle 正常生成的映射/AT 开发副本位于忽略的缓存或 `build/` 中。

## 1. Java 与 Wrapper

系统只有 Java 25 JRE，无 `javac`、无全局 Gradle。使用官方 Temurin JDK 8u504-b01 安装到 `.tools/jdk8`；保留官方 2860 MDK 的 Gradle 4.9 Wrapper，并固定 MDK 原有主版本内的 ForgeGradle 3.0.197。Java/资源源码编码为 UTF-8，字节码目标 1.8。

## 2. HTTPS 与重试

本机代理为环境提供的 HTTP CONNECT 代理。curl 默认 TLS 握手访问多个官方站点报 `unexpected eof while reading`，同一 URL 使用 TLS 1.2 后成功。下载脚本和 Gradle JVM 固定 TLS 1.2；未关闭证书校验。Java 不自动读取 shell 代理变量，项目启动脚本将无认证 HTTP 代理转成进程级 JVM 参数。

仍观察到两次单个文件的偶发 `Remote host terminated the handshake`：Minecraft 的 `minecraft/lang/ar_sa.lang` 和 ASM 的一个 JAR。均重新运行原 Gradle 命令恢复，没有跳过下载或验证。另对全部 1290 个 Minecraft 资源对象逐个校验大小与官方索引 SHA-1，全部通过。

## 3. CurseMaven 不能抢先解析开发映射版本

初版脚本使用了 Gradle 4.9 不支持的 `repositories.content`，首轮真实构建报 `Could not find method content()`。移除此语法，未升级 Wrapper 来绕过问题。

进一步检查发现，CurseMaven 对 FG3 的 `_mapped_snapshot_20171003-1.12` URL 也返回 HTTP 200 和原始模组 JAR；其 SHA-256 与官方原件完全相同。仅编译不一定暴露此问题，因为本阶段引用的 API 名称本来就未混淆。

在 FG3 注册虚拟映射仓库后，将 CurseMaven 移至仓库列表末尾。其原始依赖依旧由 CurseMaven 下载，而映射依赖先由 FG3 `DeobfuscatingRepo` 生成。编译前 `verifyDevelopmentDependencies` 拒绝缺失映射依赖和回退到已知原版哈希。已校验实际原始缓存与官方 CDN 一致、映射副本哈希不同。

依据：[FG3 UserDevPlugin](https://github.com/MinecraftForge/ForgeGradle/blob/FG_3.0/src/userdev/java/net/minecraftforge/gradle/userdev/UserDevPlugin.java)、[DeobfuscatingRepo](https://github.com/MinecraftForge/ForgeGradle/blob/FG_3.0/src/userdev/java/net/minecraftforge/gradle/userdev/util/DeobfuscatingRepo.java)。

## 4. 首次并行重映射

两个依赖首次并行重映射时曾观察到 `JarExec` 打开共享工具 JAR 抛出 `ZipException`，FG3 随后回退而仍显示构建成功。后续该工具 JAR 的 ZIP 检查正常，重新映射成功，现象与首次工具下载期间的并行访问有关；未将其定性为第三方模组损坏。

配置 `org.gradle.workers.max=1`，移走项目缓存中的重映射工具及两个映射输出，再运行 `clean build`，冷重映射通过。保留编译前检查，防止 FG3 的回退掩盖转换错误。

## 5. `Side.BUKKIT` / Forge 网络注册崩溃

首次实际客户端在 `NetworkRegistry.newChannel:207` 空指针崩溃。对比官方 Forge sources/universal 与生成的 joined/mapped JAR：前者 `Side` 只有 CLIENT/SERVER，后者包含额外的 BUKKIT。实际 MCP 1.12.2 merge 输出已带入该 helper 类；Forge 网络注册只为前两个枚举初始化 map，因此遍历第三个值时失败。

从 Forge 官方 Maven 获取未经修改的 `net.minecraftforge:mergetool:0.2.3.3:forge`，其两个 helper 类不含 BUKKIT；固定该依赖版本并将其置于开发 JavaExec classpath 最前。不是删除合并流程，也没有给 Forge 加反射补丁或修改 JAR。通过运行时探针验证 `Side.values()` 为 `[CLIENT, SERVER]`，类来源正是该官方 helper JAR。

同时将独立 ASM 组件固定到 Forge 要求的 5.2 系列，避免其旧 ASM 扫描器读取 ASM 6 发行包的 Java 9 `module-info.class` 时抛异常。独立合并/转换工具仍使用自身 fatjar，不受开发运行 classpath 对齐影响。

依据：[ForgeGradle 上游问题 #748](https://github.com/MinecraftForge/ForgeGradle/issues/748)、[MergeTool 官方 POM](https://maven.minecraftforge.net/net/minecraftforge/mergetool/0.2.3.3/mergetool-0.2.3.3.pom)；结论另由本次源码、二进制与运行时取证确认。

## 6. 依赖 Access Transformer

修正 Forge 后，客户端在 Thaumcraft `ConfigBlocks.initBlocks` 报 `IllegalAccessError: BlockRailPowered.<init>()V`。官方 Thaumcraft JAR 的 manifest 声明 `FMLAT: tc_at.cfg`，原始配置明确公开此构造器，但 FG3 没有自动将依赖 AT 应用到本工程的开发 Minecraft 副本。

新增只用于读取原件的 `thaumcraftDistribution` 配置，先核对官方原件 SHA-256，再逐字节提取 `META-INF/tc_at.cfg` 到 `.gradle/thaumcraft/tc_at.cfg`，传给 `minecraft.accessTransformer`。所有规则均来自指定 BETA26 原件，没有自行扩大访问范围。该提取文件不在 `src/main/resources`，也不进入本项目 JAR。

提取文件 SHA-256：`3c1ea5580fcd332e5b7f1fb5e727f3dabf32ebe25f96796b0b6b907d1bee2042`。应用后 Thaumcraft、Baubles、本模组全部完成初始化。

## 7. 旧版目录发现与退出行为

FML 1.12 按主类所在目录读取 `mcmod.info`。Gradle 默认分别输出 class 和 resources，导致源码运行时 Mods 详情出现 `No mod information found`，即使打包 JAR 的元数据本来正确。将处理后的资源输出到主类目录后，运行时 `metadata.autogenerated=false`，Mods 页正常显示版本、作者与描述。项目仍只有标准 `src/main/java`、`src/main/resources` 输入目录。

第一次正常游戏退出后，FG3 默认 `forceExit=true` 在 JavaExec 的 `doLast` 中调用 `System.exit(0)`，终止 Gradle daemon 并让外层报告 daemon disappeared。客户端并未在此时崩溃。为 client/server 配置 `forceExit false`，之后正常退出得到 `BUILD SUCCESSFUL`，退出码 0。另外将启动环境 `MC_VERSION` 明确设为 `1.12.2`，修正 userdev 配置中的字面占位符。

依据：[FG3 RunConfigGenerator](https://github.com/MinecraftForge/ForgeGradle/blob/FG_3.0/src/common/java/net/minecraftforge/gradle/common/util/runs/RunConfigGenerator.java)。
